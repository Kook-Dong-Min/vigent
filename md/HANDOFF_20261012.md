## 6. 지금까지 겪은 함정 (다음 세션이 다시 밟지 않게)

**테스트 간 상태 누출 3종** — 전부 "전역 상태를 바꾸고 되돌리지 않는 테스트"였다. 해결은 `tests/_isolate.py` 의 헬퍼를 setUp 에 넣는 것.
1. **토큰 모드**: 개발기 `.env` 의 `VIGENT_API_TOKEN` 이 import 시점 상수로 박혀 Mac 에서 쓴 테스트 22건이 401 — `isolate_no_token()`.
2. **종료 깃발**: 진짜 `_shutdown()`(직접 호출 또는 `TestClient` lifespan)이 `worker.manager` 의 "종료 중" 깃발·기아 감시·예열 취소 깃발을 남겨 뒤 모듈의 `start` 가 거부됨 — `isolate_shutdown()` + 정적 검사(`test_shutdown_paths.EveryRealShutdownTestRestoresFlag`).
3. **예열 스레드**: lifespan 이 띄운 `vigent-warmup`(모델 로드 20 s+)이 테스트가 끝나도 돌아 타이밍 테스트(`test_audit_fix10_watchdog`, 0.12 s 창)를 굶김 — `isolate_warmup()`. 게이트 시간도 160~200 s → 100~110 s 로 줄었다.

**러너 감지**: 경보 큐가 "테스트 러너면 임시 DB" 를 `"unittest" in sys.modules` 로 판정했는데 `import torch` 만으로 참이 돼 **진짜 서버가 10-08~10-11 임시 DB 를 썼다**. 지금은 `sys.argv[0]`(unittest/pytest/`test_*.py`)·pytest 흔적으로 본다(`alert_queue._is_test_runner`). 자체 하네스로 스위트를 돌릴 때는 파일명이 `test_` 로 시작해야 한다. 기동 로그 "경보 큐 DB: 운영" 을 확인하는 습관.

**문서의 묶음 표기**: 로그 "대기 2381건" 이 텔레그램 대기로 읽혔지만 보존 스윕의 삭제 후보 수였고, "stopped: 1" 은 돌던 워커 수가 아니라 워커 객체 수였으며, OPEN_ISSUES #14 는 종료 경로 3건과 `mark_sent` 1건이 한 줄에 묶여 있었다. **한 줄에 여러 뜻을 묶지 말고, 로그 문구는 세는 대상을 그대로 적는다**(이미 "후보"·"기록 전용 등급" 으로 고침, `stopped` 의 `was_running` 분리는 #42 미착수).

**그 밖에**: Bash heredoc 은 백슬래시를 훼손한다(패치 스크립트는 Write 도구로) · `ruff --fix` 는 변경 파일에만 · gate.ps1 의 "--fix 범위 밖" 검사는 삭제 파일을 오탐했었다(수정됨) · 프로파일 드리프트 검사는 기본 설정에 키를 넣으면 현장 프로파일에도 같은 키가 있어야 통과한다.
